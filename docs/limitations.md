# Ограничения и план развития

Прототип собран за два дня хакатона. Приоритет — работающий сквозной цикл: сценарий → разбор → награда → прогресс → рекомендация. Ниже — что сознательно упрощено и как это развивать.

## Ограничения прототипа

**Контент**
- Четыре сценария по памятке «Ситуации на борту» — по одному на категорию. В памятке 51 ситуация, формат YAML уже готов для остальных.
- Метки навыков у вариантов ответа — черновик команды, методисту стоит их выверить.
- Контент правится только в YAML-файлах, редактора в интерфейсе нет. Истории изменений сценариев нет, кроме истории Git.

**Геймификация и аналитика**
- **Уведомления** — только всплывающие тосты: новый уровень и ачивки. Центра уведомлений со списком нет, колокольчик пока ведёт на заглушку. Напоминаний о новых сценариях, челленджей и сгорающих баллов из ТЗ нет — канал для них готов, это событие `notification.requested`.
- **Роль `MANAGER`** пока ничем не отличается от проводника: сводки пробелов по бригаде для руководителя нет.
- **Навыки** — процент верных решений за 10 последних прохождений, без истории изменений во времени.
- **Рейтинг** учитывает только проводников с назначенной бригадой; месяц считается по Москве (UTC+3).

**Интеграции**
- API для HR, LMS и учёта обучения описан в Swagger (`/api/docs`), готовых интеграций нет. Ответы в Swagger показаны примерами, а не строгими схемами.
- Внешняя система может читать события из стрима Redis, но выделенного API для этого — вебхуков, xAPI — нет.

**Инфраструктура и безопасность**
- Одно приложение ядра без горизонтального масштабирования. SSE и подписка на события живут в памяти экземпляра.
- Пароли и секрет JWT в `docker-compose.yml` — для разработки. Нет HTTPS, ограничения частоты запросов и аудита действий администратора.
- Нет офлайн-режима: проводнику в поезде нужна связь.
- Только синтетические данные: демо-сотрудники и штат из 35 вымышленных проводников.

## План развития

| Этап | Что | Зачем |
|---|---|---|
| **1. Пилот в одном депо** | 15–20 сценариев из памятки и СТО РЖД 03.011 (классы, нормы ожидания, режим тишины), выверенные методистом метки навыков | контент покрывает основные ситуации смены |
| | Центр уведомлений: новые сценарии для бригады, напоминание «давно не тренировались», итоги месяца в рейтинге | регулярность тренировок |
| | Кабинет руководителя: пробелы бригады по навыкам, кто давно не тренировался, назначить сценарий | руководитель управляет обучением, а не только смотрит рейтинг |
| **2. Масштаб на компанию** | Редактор сценариев с предпросмотром графа, проверкой достижимости узлов и версиями | методисты работают без Git |
| | Интеграция с LMS и HR: выгрузка результатов (xAPI), единый вход (SSO), синхронизация штата и бригад | тренажёр — часть корпоративного обучения |
| | Челленджи бригад и сезонные рейтинги, сгорающие баллы | удержание интереса после первых недель |
| **3. Развитие продукта** | Сценарии с фото салонов и звуком, режим для планшета проводника, офлайн-прохождение с синхронизацией | ближе к реальной обстановке в поезде |
| | ИИ-помощник в разборе: объясняет ошибку своими словами по регламенту — отдельный модуль, отключается без ключа | персональная обратная связь |
| | Аналитика во времени: тренды навыков по сотруднику, бригаде и депо | видно, работает ли обучение |
| | Эксплуатация: HTTPS, секреты вне репозитория, ограничение частоты запросов, аудит, несколько экземпляров ядра | промышленная эксплуатация |

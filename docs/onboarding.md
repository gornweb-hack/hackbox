# Старт для разработчика модуля ядра

Бэкенд — одно приложение на Nest.js (`core/`), собранное из модулей. Предметная часть тренажёра — тоже модули ядра, у каждого свой владелец:

| Модуль | Папка | Что делает |
|---|---|---|
| `scenarios` | `core/src/scenarios/` | движок сценариев: прохождение, таймеры, две шкалы, финалы, разбор решений |
| `gamification` | `core/src/gamification/` | очки компетенций, уровни, ачивки, рейтинг, уведомления |
| `analytics` | `core/src/analytics/` | профиль компетенций, пробелы, выводы и рекомендации |

## 0. Подготовить машину

- Git и Docker Desktop (запущен, «Engine running»).
- Node.js 24.15 или новее: этого требует Nest CLI 12.
- VS Code с расширениями Docker и Prisma.
- Доступ к репозиторию `gornweb-hack/hackbox`.

## 1. Поднять проект (≈15 минут)

```bash
git clone git@github.com:gornweb-hack/hackbox.git
cd hackbox
docker compose up -d --build
```

- Если порт занят другим проектом, скопируйте `.env.example` в `.env` и поменяйте порт.

## 3. Как устроено ядро

`core/src/app.module.ts` — список модулей. Сейчас их четыре, все, кроме последнего, глобальные: их сервисы доступны любому модулю без импорта.

| Модуль | Что даёт другим модулям |
|---|---|
| `PrismaModule` (`prisma/`) | `PrismaService` — доступ к базе |
| `EventsModule` (`events/`) | `EventsService` — публикация событий; SSE `/api/stream` |
| `AuthModule` (`auth/`, `users/`) | вход и сотрудники; `AuthGuard`, `@Roles`, `@CurrentUser` для своих эндпоинтов |
| `HealthModule` (`health/`) | `GET /api/health` |

## 4. Свой модуль — по шагам

1. **Папка** `core/src/<name>/`. В ней `<name>.module.ts`, контроллер, сервис, DTO и тесты `*.spec.ts` рядом с кодом.
2. **Модуль:**
   ```ts
   import { Module } from '@nestjs/common';
   import { ScenariosController } from './scenarios.controller.js';
   import { ScenariosService } from './scenarios.service.js';

   @Module({
     controllers: [ScenariosController],
     providers: [ScenariosService],
   })
   export class ScenariosModule {}
   ```
3. **Подключение** — строка в `imports` в `core/src/app.module.ts`. Эту строку владелец модуля добавляет сам.
4. **Эндпоинты** закрываются входом и ролью:
   ```ts
   @Controller('scenarios')
   @UseGuards(AuthGuard)
   export class ScenariosController {
     @Post('runs')
     start(@CurrentUser() user: AuthUser, @Body() dto: StartRunDto) { ... }

     @Get('stats')
     @Roles(['MANAGER', 'ADMIN'])
     stats() { ... }
   }
   ```
   Глобальный префикс `api` ставит `main.ts`, поэтому путь будет `/api/scenarios/runs`.
5. **Ошибки** — `throw new ApiError(404, 'RUN_NOT_FOUND', 'Прохождение не найдено')`. Код в UPPER_SNAKE_CASE, сообщение по-русски.
6. **Валидация** — DTO на class-validator, как в `core/src/auth/dto.ts`. Ошибка приходит сама: `422 VALIDATION_ERROR`. Лишние поля тела отбрасываются.
7. **Формат ответов:**
   - JSON в camelCase;
   - даты — ISO 8601 в UTC;
   - идентификаторы — UUID;
   - списки — `{items, total}`.
8. **Настройки** — только из переменных окружения: поле в `core/src/config.ts`, значение в `docker-compose.yml` у сервиса `core` и пример в `core/.env.example`.
9. **ESM.** Относительные импорты пишутся с `.js`: `./scenarios.service.js`.

## 5. База

- **Модели** своего модуля — в `core/prisma/schema.prisma`, отдельным блоком с комментарием-заголовком. У таблиц префикс модуля: `@@map("scenario_runs")`.
- **Модуль пишет только в свои таблицы.** Нужны чужие данные — через сервис владельца или копию из событий.
- **Миграция** — `npx prisma migrate dev --name <имя>` в `core/`. Папка миграций одна на всю команду, поэтому:
  - перед созданием миграции сделайте `git pull` и предупредите команду;
  - после создания сразу закоммитьте.
- Подробно — в [памятке по базе](database.md).

## 6. События

- **Публикация** — `EventsService.publish(type, data, { userId })`.
- **Обработка** событий в своём модуле подключается через `EventsConsumer`. Это инфраструктура ядра, правку согласуйте с техлидом.
- **Обработчики идемпотентны.**
- Подробно — в [памятке по событиям](events.md).

## 7. Договорённости по предметной части

Их нужно обсудить на первом созвоне и записать в `docs/`.

- **Формат сценария (YAML).** Узлы, варианты ответа, эффекты на «лояльность» и «безопасность», таймер и ветка на случай, если время истекло, условия переходов, тексты разбора. Ведёт владелец `scenarios`: это контракт между движком, фронтом и геймификацией.
- **Событие `scenario.completed`.** Его публикует движок, а геймификация и аналитика читают. `userId` проводника — в конверте. Черновик `data` для обсуждения:
  ```json
  {"runId": "uuid", "scenarioId": "conflict-seat", "outcome": "good",
   "loyalty": 72, "safety": 85, "timeouts": 1, "durationSec": 184,
   "competencies": {"conflict": 4, "standards": 2},
   "decisions": [{"nodeId": "n1", "choiceId": "check", "timedOut": false, "loyaltyDelta": 10, "safetyDelta": 5}]}
  ```
  Итоговый формат записать в таблицу стандартных событий в [памятке](events.md).
- **Компетенции.** Единый справочник (`conflict`, `medical`, `standards`, …) и связь «сценарий → компетенции». По ней аналитика рекомендует сценарий под пробел.
- **Живая правка на защите.** Сценарии лежат в папке, которая монтируется в контейнер ядра и перечитывается без пересборки. Тогда правка развилки занимает минуту.

## 8. Задачи на первый день

**`scenarios`:**
1. Один сценарий из YAML проходится через API:
   - `POST /api/scenarios/runs {scenarioId}` → первый узел;
   - `POST /api/scenarios/runs/{id}/choices {choiceId}` → сервер сам проверяет, не истёк ли таймер, применяет эффекты к обеим шкалам и отдаёт следующий узел или финал;
   - `GET /api/scenarios/runs/{id}/report` → разбор каждого решения.
2. Неверный или повторный выбор и выбор после финала дают понятные ошибки 4xx.
3. В финале публикуется `scenario.completed`. С этого момента геймификация и аналитика получают данные.

**`gamification`:**
1. Обработка `scenario.completed`: начисление очков компетенций, повтор отсекается по `runId`.
2. Уровни и ачивки — по правилам из YAML, чтобы их можно было поправить при жюри.
3. `GET /api/gamification/leaderboard` и `GET /api/gamification/me/progress` для фронта.
4. При новой ачивке — `notification.requested` проводнику.

**`analytics`:**
1. Обработка `scenario.completed`: результаты — в своих таблицах, повтор отсекается по `runId`.
2. `GET /api/analytics/me/competencies` — профиль проводника:
   - очки по каждой компетенции и сколько сценариев пройдено;
   - средние «лояльность» и «безопасность», доля таймаутов;
   - что освоено, а что проседает.
3. `GET /api/analytics/me/insights` — выводы текстом, а не сырые цифры. Например: «Конфликты решаете уверенно; в медицинских ситуациях 2 из 3 решений снизили безопасность — рекомендуем сценарий "Пассажиру плохо"».
4. Синтетические данные для демо:
   - сотрудники — через `POST /api/users` под админом;
   - прохождения — через API движка.

   Тогда рейтинг и аналитика на демо не будут пустыми.

## 9. Цикл разработки

- **Быстро — без Docker для ядра.** База и Redis работают в Docker, ядро запускается с перезапуском при изменениях:
  ```bash
  docker compose up -d postgres db-init redis
  ```
  ```bash
  docker compose stop core
  ```
  Затем в `core/`:
  ```bash
  cp .env.example .env
  ```
  ```bash
  npm install
  ```
  ```bash
  npm run start:dev
  ```
  В `.env` поправьте порт базы под свой `POSTGRES_PORT`. Фронт в Docker ходит в ядро по адресу, заданному при сборке, поэтому с ядром на хосте проверяйте API напрямую на `http://127.0.0.1:4000/api/...`.
- **Проверки** в `core/`: `npm test`, `npm run lint`, `npm run build`.
- **Интеграция** — в контейнере: `docker compose up -d --build core`. Логи — `docker compose logs -f core`.

## 10. Git и самостоятельность

- **Свой код — только в своей папке** `core/src/<name>/` и в своём блоке `schema.prisma`.
- **ИИ-помощник работает в зоне своего модуля** ([AGENTS.md](../AGENTS.md), раздел «Зоны ответственности агента»). Если нужна правка в инфраструктуре ядра или на фронте, агент опишет, что поменять, а вы передадите это владельцу.
- **`git pull` — несколько раз в день.** Коммиты маленькие и осмысленные: `feat(scenarios): add timer timeout branch`. Жюри смотрит историю.
- **Понимайте каждую строку.** ИИ как помощник можно, но на защите попросят за пару минут поменять развилку или правило и объяснить, почему движок устроен так.
- **Тесты на предметную логику** — и страховка при правках, и аргумент на защите.
- **Данные только синтетические:** никаких реальных ФИО и табельных номеров.

# Старт для разработчика модуля ядра

Бэкенд — одно приложение на Nest.js (`core/`), собранное из модулей. Предметная часть тренажёра — тоже модули ядра:

| Модуль | Папка | Что делает | Где читать |
|---|---|---|---|
| `scenarios` | `core/src/scenarios/` | каталог, прохождение с таймером и двумя шкалами, разбор, событие `scenario.completed`, демо-история | [API](api.md#сценарии), [контент](content.md) |
| `gamification` | `core/src/gamification/` | журнал из `scenario.completed`, опыт, уровни, репутация, ачивки, награда, рейтинг за месяц | [API](api.md#геймификация), [контент](content.md#правила-геймификации) |
| `analytics` | `core/src/analytics/` | навыки ролевой модели по меткам в YAML, слабый навык, рекомендация сценария | [API](api.md#аналитика), [контент](content.md#навыки) |
| `notifications` | `core/src/notifications/` | центр уведомлений из `notification.requested`, счётчик непрочитанных | [API](api.md#уведомления-и-поток-событий) |

Как они связаны — в [README](../README.md#архитектура) и [архитектуре](architecture.md). Что осталось сделать — в [плане развития](limitations.md#план-развития).

## 0. Подготовить машину

- Git и Docker Desktop (запущен, «Engine running»).
- Node.js 24.15 или новее: этого требует Nest CLI 12.
- VS Code с расширениями Docker и Prisma.
- Доступ к репозиторию `gornweb-hack/hackbox`.

## 1. Поднять проект (≈15 минут)

```bash
git clone git@github.com:gornweb-hack/hackbox.git
cd hackbox
docker compose up -d --build
```

- Откройте http://127.0.0.1:3000 и войдите под `user` / `user123`.
- Если порт занят другим проектом, скопируйте `.env.example` в `.env` и поменяйте порт.
- Подробности запуска — в [README](../README.md#быстрый-старт).

## 3. Как устроено ядро

`core/src/app.module.ts` — список модулей: служебные ниже и предметные из таблицы в начале. Первые три служебных — глобальные: их сервисы доступны любому модулю без импорта.

| Модуль | Что даёт другим модулям |
|---|---|
| `PrismaModule` (`prisma/`) | `PrismaService` — доступ к базе |
| `EventsModule` (`events/`) | `EventsService` — публикация событий; SSE `/api/stream` |
| `AuthModule` (`auth/`, `users/`) | вход и сотрудники; `AuthGuard`, `@Roles`, `@CurrentUser` для своих эндпоинтов |
| `HealthModule` (`health/`) | `GET /api/health` |

## 4. Свой модуль — по шагам

1. **Папка** `core/src/<name>/`. В ней `<name>.module.ts`, контроллер, сервис, DTO и тесты `*.spec.ts` рядом с кодом.
2. **Модуль:**
   ```ts
   import { Module } from '@nestjs/common';
   import { ScenariosController } from './scenarios.controller.js';
   import { ScenariosService } from './scenarios.service.js';

   @Module({
     controllers: [ScenariosController],
     providers: [ScenariosService],
   })
   export class ScenariosModule {}
   ```
3. **Подключение** — строка в `imports` в `core/src/app.module.ts`.
4. **Эндпоинты** закрываются входом и ролью:
   ```ts
   @Controller('scenarios')
   @UseGuards(AuthGuard)
   export class ScenariosController {
     @Post('runs')
     start(@CurrentUser() user: AuthUser, @Body() dto: StartRunDto) { ... }

     @Get('stats')
     @Roles(['MANAGER', 'ADMIN'])
     stats() { ... }
   }
   ```
   Глобальный префикс `api` ставит `main.ts`, поэтому путь будет `/api/scenarios/runs`.
5. **Ошибки** — `throw new ApiError(404, 'RUN_NOT_FOUND', 'Прохождение не найдено')`. Код в UPPER_SNAKE_CASE, сообщение по-русски.
6. **Валидация** — DTO на class-validator, как в `core/src/auth/dto.ts`. Ошибка приходит сама: `422 VALIDATION_ERROR`. Лишние поля тела отбрасываются.
7. **Формат ответов:**
   - JSON в camelCase;
   - даты — ISO 8601 в UTC;
   - идентификаторы — UUID;
   - списки — `{items, total}`.
8. **Настройки** — только из переменных окружения: поле в `core/src/config.ts`, значение в `docker-compose.yml` у сервиса `core` и пример в `core/.env.example`.
9. **ESM.** Относительные импорты пишутся с `.js`: `./scenarios.service.js`.
10. **Swagger** (`/api/docs`) — у контроллера `@ApiTags('Группа')` и `@ApiAuth()` из `core/src/common/swagger.ts`, у эндпоинта — `@ApiOperation({ summary: '…' })`. Схемы тел запросов строит плагин Nest CLI из классов в файлах `dto.ts`, поэтому отдельных `@ApiProperty` не нужно. Ответы у нас — интерфейсы, их плагин не видит: для важных эндпоинтов добавьте `@ApiOkResponse({ example })` с примером из `api-examples.ts` модуля.

## 5. База

- **Модели** своего модуля — в `core/prisma/schema.prisma`, отдельным блоком с комментарием-заголовком. У таблиц префикс модуля: `@@map("scenario_runs")`.
- **В таблицы другого модуля напрямую не писать.** Его данные — через его сервис или копию из событий.
- **Миграция** — `npx prisma migrate dev --name <имя>` в `core/`. Папка миграций одна на всю команду, поэтому:
  - перед созданием миграции сделайте `git pull` и предупредите команду;
  - после создания сразу закоммитьте.
- Подробно — в [памятке по базе](database.md).

## 6. События

- **Публикация** — `EventsService.publish(type, data, { userId })`.
- **Обработка** событий в своём модуле подключается через `EventsConsumer`.
- **Обработчики идемпотентны.**
- Подробно — в [памятке по событиям](events.md).

## 7. Договорённости по предметной части

Команда их приняла, подробности — в `docs/`.

- **Формат сценария (YAML)** — в [памятке по контенту](content.md): узлы, варианты, влияние на шкалы, таймер и ветка «время вышло», условия переходов, тексты разбора.
- **Событие `scenario.completed`** публикует движок в финале прохождения, `userId` проводника — в конверте. Формат `data` — в таблице стандартных событий [памятки](events.md). Его читает геймификация, а фронт по нему перечитывает навыки.
- **Навыки.** Справочник — `content/skills.yaml` (шаги ролевой модели, безопасность, хладнокровие), метки `skills` — у вариантов ответа. По ним аналитика находит слабый навык и рекомендует сценарий ([памятка по контенту](content.md#навыки)).
- **Живая правка на защите.** Папка `content/` монтируется в контейнер ядра и читается при каждом запросе, поэтому правка развилки занимает минуту. Рецепт — в [памятке по контенту](content.md#правка-при-жюри).

## 8. Цикл разработки

- **Быстро — без Docker для ядра.** База и Redis работают в Docker, ядро запускается с перезапуском при изменениях:
  ```bash
  docker compose up -d postgres db-init redis
  ```
  ```bash
  docker compose stop core
  ```
  Затем в `core/`:
  ```bash
  cp .env.example .env
  ```
  ```bash
  npm install
  ```
  ```bash
  npm run start:dev
  ```
  В `.env` поправьте порт базы под свой `POSTGRES_PORT`. Фронт в Docker ходит в ядро по адресу, заданному при сборке, поэтому с ядром на хосте проверяйте API напрямую на `http://127.0.0.1:4000/api/...`.
- **Проверки** в `core/`: `npm test`, `npm run lint`, `npm run build`.
- **Интеграция** — в контейнере: `docker compose up -d --build core`. Логи — `docker compose logs -f core`.

## 9. Git и самостоятельность

- **Работайте в своём модуле.** Нужно поменять модуль коллеги — сначала договоритесь с ним: так вы не правите одно место параллельно.
- **Изменился API — сообщите команде фронтенда** и обновите [справочник API](api.md).
- **`git pull` — несколько раз в день.** Коммиты маленькие и осмысленные: `feat(scenarios): add timer timeout branch`. Жюри смотрит историю.
- **Понимайте каждую строку.** ИИ как помощник можно, но на защите попросят за пару минут поменять развилку или правило и объяснить, почему движок устроен так.
- **Тесты на предметную логику** — и страховка при правках, и аргумент на защите.
- **Данные только синтетические:** никаких реальных ФИО и табельных номеров.

# Контракт модуля

Модуль — отдельный сервис на любом языке. Здесь перечислено всё, что он обязан уметь, чтобы ядро и фронт с ним работали. Фреймворк и структура кода — на усмотрение владельца. Как подключить модуль к проекту, описано в [README](../README.md#модули).

## Имя

Одно имя на всё: папка `modules/<name>`, сервис в [docker-compose.yml](../docker-compose.yml), схема и роль в базе, путь `/api/m/<name>/` у ядра.

Формат `^[a-z][a-z0-9_]*$`, нельзя `core`, `public`, `pg`, `pg_*`.

| Модуль | Порт для отладки |
|---|---|
| `tpl_go` | 8101 |
| `tpl_py` | 8102 |
| следующий | 8103 и дальше по порядку |

## Обязательно

1. **Запуск.** `Dockerfile` лежит в `modules/<name>/`. Сервис слушает `0.0.0.0:$PORT` (в compose `PORT=8080`). Настройки берутся только из переменных окружения.

2. **`GET /health`** отвечает `200 {"status":"ok"}`, когда модуль готов работать, включая связь с базой, если она нужна. Иначе `503`. Ответ быстрый, без тяжёлой логики: ядро опрашивает его и скрывает модуль, который не отвечает.

3. **`GET /openapi.json`** отдаёт спецификацию API, сгенерированную из кода: FastAPI делает это сам, в Go — [huma](https://huma.rocks). По ней фронт генерирует типы.

4. **API.** Пути любые, кроме `/health` и `/openapi.json`. Фронт вызывает `/api/m/<name>/<путь>`, ядро отрезает префикс, и модуль получает `/<путь>`.

5. **Пользователь.** Ядро проверяет вход и передаёт заголовок `X-User-Id` (UUID). Модуль ему доверяет. Если эндпоинту нужен пользователь, а заголовка нет, модуль отвечает `401`.

6. **JSON.** Поля в camelCase, даты в ISO 8601 и UTC (`2026-09-25T12:00:00Z`), идентификаторы — UUID. Список отдаётся как `{"items": [...], "total": 42}`.

7. **Ошибки.** HTTP-статус и тело:
   ```json
   {"code": "NOT_FOUND", "message": "Заметка не найдена"}
   ```
   `code` пишется в UPPER_SNAKE_CASE, по нему фронт решает, что делать. `message` — для человека. Ошибка валидации — `422` с `"code": "VALIDATION_ERROR"`. У FastAPI, huma и Nest формат ошибок по умолчанию другой, нужен свой обработчик.

8. **База.**
   - Подключение из `DATABASE_URL` под своей ролью `<name>_svc`.
   - `search_path` роли уже указывает на свою схему, поэтому таблицы пишутся без префикса.
   - Чужие схемы недоступны. Чужие данные берутся через API их владельца.
   - Миграции свои (goose, Alembic и т. п.), применяются при старте сервиса.

9. **Надёжность.**
   - Если при старте база недоступна, модуль повторяет попытки или завершается с ошибкой: Docker перезапустит его сам (`restart: unless-stopped`).
   - Все исходящие HTTP-вызовы идут с таймаутом. Другой модуль доступен по `http://<имя>:8080` и в любой момент может не ответить.
   - По SIGTERM модуль завершается корректно.

10. **Логи** пишутся в stdout.

**Желательно:** писать в логи `X-Request-Id`, если ядро его передало. По нему легко найти один запрос в логах разных сервисов.

## Проверка своего модуля

Через ядро: модуль должен появиться в `http://127.0.0.1:4000/api/modules` со статусом `up`, а его API — отвечать на `http://127.0.0.1:4000/api/m/<name>/<путь>`.

Напрямую, в обход ядра, заголовок пользователя подставляется вручную (пока нет входа пользователей, иначе его и не получить):

```bash
curl -i http://127.0.0.1:8101/health
curl http://127.0.0.1:8101/openapi.json
curl -H "X-User-Id: 00000000-0000-0000-0000-000000000001" http://127.0.0.1:8101/<путь>
```

В PowerShell вместо `curl` пишите `curl.exe`.
